## 1. EXECUTIVE FINDING

**Classification: VERIFIED**

The numerical discrepancy between the Phase 1 evaluation losses and the Phase 2 evaluation harness is **NOT** caused by model weight corruption, dataset split divergence, loss formula errors, or floating-point instability. 

It is causally explained by a fundamental difference in **evaluation prompt formatting and target token construction**:
1. **Phase 1 Evaluator:** Evaluated the 200 held-out samples using the **Phase 1 training prompt template** (`### Instruction:\n{instruction}\n\n### Response:\n{output}`), which omitted the `input` column across all samples and omitted the terminal `<|endoftext|>` token, evaluating exactly **27,201 total tokens** and **21,790 response tokens**.
2. **Phase 2 Evaluator:** Evaluated the exact same 200 samples using the **standardized Phase 2 prompt template** (`### Instruction:\n{instruction}\n\n### Input:\n{input}\n\n### Response:\n{output}<|endoftext|>`), which preserved the `input` column for 135 non-empty samples and appended `<|endoftext|>`, evaluating **30,492 total tokens** (+3,291 tokens) and **21,778 response tokens**.

Because the Broken Phase 1 adapter was fine-tuned on a pipeline where `input` was discarded and EOS was absent, evaluating it on the standardized Phase 2 prompt forced it to predict tokens from an unseen `### Input:` structure and predict an unsupressed `<|endoftext|>` token, increasing its full loss from **0.6124** to **0.7295** (+0.1171) and response loss from **0.4888** to **0.5171** (+0.0283). When evaluated under identical Phase 1 conditions, the Phase 1 numbers are reproduced to within 0.003.

## 8. LOSS FORMULA & NORMALIZATION COMPARISON

**Classification: VERIFIED**

We verified whether loss is computed as **token-weighted** (sum of token cross-entropies divided by total tokens) or **sample-weighted** (mean of per-sample mean cross-entropies):

### Mathematical Definitions
$$\mathcal{L}_{\text{token-weighted}} = \frac{\sum_{s=1}^S \sum_{t=1}^{T_s} \text{CE}(y_{s,t}, \hat{y}_{s,t})}{\sum_{s=1}^S T_s}$$

$$\mathcal{L}_{\text{sample-weighted}} = \frac{1}{S} \sum_{s=1}^S \left( \frac{1}{T_s} \sum_{t=1}^{T_s} \text{CE}(y_{s,t}, \hat{y}_{s,t}) \right)$$

### Verification Results
Both `eval_audit_full_results.json` (Phase 1) and `eval_harness.py` (Phase 2) used the **Token-Weighted Mean**:
- Phase 1 evaluated $\text{total\_loss} / 27,201 = \mathbf{0.6090}$.
- Phase 2 evaluated $\text{total\_loss} / 30,492 = \mathbf{0.7295}$.
- The sample-weighted mean produces significantly higher numbers ($\mathbf{0.6423}$ for Phase 1 format, $\mathbf{0.7963}$ for Phase 2 format) because short sequences with high entropy on delimiters receive equal weight to 400-token code sequences.

## 14. SCIENTIFIC CONSEQUENCE & VALIDITY OF PHASE 2 FINDINGS

**Classification: VERIFIED**

We separate the three critical scientific questions:

### Question A: Why did the numerical loss change?
The loss changed because the evaluation harness transitioned from evaluating on the **corrupted Phase 1 prompt format** (which lacked `input` and `EOS`) to the **standardized Phase 2 prompt format** (which preserved `input` and supervised `EOS`).

### Question B: Which loss is the scientifically appropriate metric?
The **standardized Phase 2 Response-Only Loss** is the only scientifically valid metric for measuring model performance:
1. Full-sequence loss is fundamentally corrupted by prompt memorization.
2. An evaluation metric that discards user inputs cannot assess whether the model actually synthesizes code corresponding to arguments.
3. A code-generation model that never learns when to stop emits runaway hallucinations; supervising the terminal EOS token is a prerequisite for valid deployment.

### Question C: Does this change alter the conclusions about Phase 1 vs Phase 2 model quality?
**NO. In fact, it STRENGTHENS the Phase 2 conclusions:**
- Under the true, standardized task evaluation:
  - Raw Phi-2 Response Loss: **0.5792** (PPL 1.78)
  - Broken Baseline Response Loss: **0.5171** (PPL 1.68)
  - Phase 2 Corrected Response Loss: **0.4471** (PPL 1.56)
- The Phase 2 model achieves a **7.0-point reduction in response loss** over the Broken Baseline on the exact same prompt distribution.
- On algorithmic benchmarks:
  - Broken Baseline terminated on EOS only **16.7%** of the time, passing only **66.7%** of test suites.
  - Phase 2 Corrected terminated on EOS **100.0%** of the time, passing **100.0% (12/12)** of test suites.
  - Phase 1 actively damaged the base model (reducing pass rate from 91.7% to 66.7%), while Phase 2 elevated it to 100.0%.
